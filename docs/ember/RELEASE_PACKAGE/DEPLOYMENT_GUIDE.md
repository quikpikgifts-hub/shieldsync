# Ember — Deployment Guide (Summary)

Full copy-paste-ready commands: `../DEPLOYMENT_CHECKLIST.md`. AWS prerequisites and what's
automated vs. manual: `../AWS_SETUP_GUIDE.md`. This page is the map; those two are the
territory.

## The path, in order

1. **Prerequisites** — real AWS account, a deploy IAM identity, Terraform ≥1.6.0 with real
   registry access (this project's build environments have never had this — confirm it
   before starting), and a decision on whether the GHCR container image is public or needs
   repository credentials configured.
2. **Remote state** — create an S3 bucket + DynamoDB lock table for Terraform state before
   the first real `apply`; local state is fine for review, not for a real deployment.
3. **`terraform init` → `plan` → `apply`** — provisions the VPC, RDS, ElastiCache, S3,
   Secrets Manager, ECS cluster/service/ALB. Nothing manual once variables are set
   correctly (`environments/production.tfvars`).
4. **Database migrations** — `prisma migrate deploy` against the real RDS instance, via an
   SSM tunnel or bastion (RDS is not publicly accessible, by design), then `prisma db seed`
   once for the RBAC catalog.
5. **Fill in remaining secrets** — SMTP/Sentry values, once a vendor is chosen; everything
   else (DB/Redis/S3 credentials, JWT signing secret) is auto-generated by Terraform.
6. **Confirm the image is published** — `backend-deploy.yml` builds and pushes to GHCR
   automatically on push to `main`.
7. **Smoke test** — `curl` the health endpoints, then run
   `backend/scripts/launch-verification.mjs` against the real URL. **This, not a clean
   `terraform apply`, is what actually confirms the deployment works.**
8. **Rollback path** — `workflow_dispatch` on `backend-deploy.yml` with a previous image
   tag; check for migrations needing a compensating rollback first.
9. **Domain/TLS** — optional, `enable_dns=true` once a real domain is owned; re-run smoke
   tests against the real HTTPS URL afterward.

## What's automatic vs. what needs a human

| Automatic (Terraform/CI) | Manual, one-time |
|---|---|
| VPC, subnets, security groups, NAT/IGW | AWS account creation, billing |
| RDS, ElastiCache, S3, Secrets Manager | GitHub OIDC deploy role (exact policy in `AWS_SETUP_GUIDE.md` §2) |
| ECS cluster/service/ALB | Domain registration/ownership |
| Container image build + push (on `git push`) | Email vendor account + domain verification |
| Migration + deploy (once secrets are set) | CloudWatch alarms (not yet built — see `../TERRAFORM_READINESS.md`) |

Every "manual" item above has step-by-step instructions in `../AWS_SETUP_GUIDE.md`.
